# TVP VOD proxy 0.0.5

Recording-safety and owned-session lifecycle fixes.

- **Intentional behavior change:** an established response no longer respawns
  FFmpeg or re-resolves a source to concatenate another media timeline. Fatal
  failures abort the transfer; clients must start a new request explicitly.
- Metadata-only HEAD does not resolve a channel, request provider media or spawn
  FFmpeg. It does not certify live channel availability.
- Both video and audio are mandatory; bootstrap is bounded and each track must
  remain active. Audio cannot hide a stalled video track or vice versa.
- Bound unread-client sends/drains, cancel startup on shutdown, and reap owned
  children before releasing admission capacity.
- Keep existing metrics/dashboard names; obsolete recovery counters remain zero.

Native77-test verification and one independent review/fix pass are recorded in
the recording-safety acceptance report. A CI follow-up adds a deterministic
split-HTTP-chunk fixture regression (78 native Rust tests total); payload and
byte/capacity/disconnect assertions remain unchanged. Production stream code is
unchanged by that test correction. A distinct bootstrap-cancellation end
reason remains a minor telemetry limitation. Source publication does not imply
actual Jellyfin DVR, seeking or lip-sync acceptance.

Release promotion requires successful CI for the exact main commit and native
amd64/arm64 image gates. Versioned GHCR images and stable `latest` publication
do not deploy or restart the running TVP/WG/Jellyfin stack. Deployment and image
digest changes require a separate operator-approved recording-safe window.
